# Portfolio Organization & Project Classification

**Business Analytics Portfolio | Evolve with Kiea**

**Purpose:** A single, consistent system for organizing existing and future projects across tools, business domains, platforms, industries, and AI methods.

## The Core Rule: One Project, One Primary Home

Each actual project has one canonical folder containing its working files, documentation, evidence, and status. Other relevant portfolio sections link to it as **subject indexes** or **method indexes**; they do not copy the workbook, code, dashboard, or results.

The same dataset may support multiple projects only when each has a materially distinct business question, method, evaluation, and deliverable. Document the relationship and reuse rather than claiming unrelated work.

## Project Classification

| Type | Meaning | When to use | Example |
|---|---|---|---|
| **Standalone** | Independent question, scope, analysis and deliverable | A genuinely new case study | Brand Partnership & Payment Tracker |
| **Extension** | New capability built on an existing project or dataset | Add a verified AI narrative, SQL replication, or forecast to a completed baseline | AI-Assisted Sales Performance Analysis extending Excel Sales Analysis |
| **Integrated case study** | One substantial end-to-end solution combining methods or functions | Financial + marketing + BI + automation in one coherent decision workflow | Creator Executive Dashboard |

A planned extension is **not** evidence that its base project exists or is complete. If the base is only an idea, both remain planned.

## Primary Home Decision Rules

1. **Existing files win:** Keep a functioning project in its existing canonical folder unless there is a documented reason to migrate it.
2. **Tool-led learning project:** Use the relevant tool folder (Excel, SQL, Python, Power BI). Add domain and AI links from indexes.
3. **Domain-led independent case study:** Use the relevant specialization folder once development starts (Creator Economy, Industry-Specific, Platform-Specific, etc.).
4. **Extension:** Add a clearly named subfolder or linked companion case study under the existing project when practical; otherwise create a distinct project folder with an explicit `Extends:` link.
5. **Integrated case study:** Choose one primary business outcome and one canonical folder; link to it from all relevant indexes.
6. **Planning ideas:** Keep them in the roadmap or category README. Do not create empty project folders merely for a planned idea.

## Standard Project Metadata

Include these fields in the project README or tracking record:

| Field | What to record |
|---|---|
| Project ID | Stable identifier; preserve existing Creator Economy IDs 31–42 |
| Title | Clear business-facing project name |
| Type | Standalone / Extension / Integrated case study |
| Primary home | Canonical relative folder path, only after it exists |
| Extends / integrates | Actual related project links; use “Proposed” if not built |
| Domain | Finance, marketing, creator economy, industry, etc. |
| Platform | Shopify, GA4, QuickBooks, etc., only if actually used |
| Tools | Excel, SQL, Python, Power BI, etc.; distinguish planned from used |
| AI method | None / AI-assisted explanation / ML forecasting / NLP / automation |
| Status | Planned / In Progress / Draft for Review / Verified / Portfolio-Ready |
| Dataset | Synthetic / public licensed / authorized, with source and scope |
| Evidence | Links to actual working files, validation and findings |
| Next action | One realistic, testable step |

## Unified Workflow and Status

**Idea → Scope → Prioritize → Prepare → Analyze / Build → Validate → Interpret → Document → Publish → Improve**

Use the five status labels in the [project documentation standards](Project-Documentation-Standards.md) for specialization planning; retain specific existing project wording where evidence requires it. Do not equate a created README with an implemented project.

## Anti-Duplication Review Before Starting

- [ ] Search existing portfolio projects for the same business question and dataset.
- [ ] Decide whether this is a standalone project, extension, or integrated case study.
- [ ] Identify a single primary folder and stable ID.
- [ ] Record relationships and distinguish new work from reused work.
- [ ] Confirm data rights and privacy.
- [ ] Define baseline, method, evaluation and expected deliverable.
- [ ] Update roadmap and category indexes, without copying working files.
- [ ] Only mark work verified when supporting evidence exists.
