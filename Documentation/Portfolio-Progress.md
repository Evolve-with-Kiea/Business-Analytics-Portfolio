# 2. Project Status Definitions

Project statuses must accurately represent the work completed.

| Status | Definition | Evidence Required |
|---|---|---|
| Planned | Project identified but work has not begun | Project idea or proposed scope |
| Practicing | Completing exercises or tutorials to develop prerequisite skills | Practice notes or exercises, where available |
| In Progress | Actively developing the defined portfolio project | Working files or documented project activity |
| Completed | Project finished and documented according to established standards | Final deliverables and supporting evidence |
| Reviewed | Completed project checked against quality standards, with external feedback where available | Review checklist and notes |

### Additional Tracking Labels

The following labels may be used separately from the official project status.

| Label | Meaning |
|---|---|
| Priority 1 | Foundational project to consider first |
| Priority 2 | Intermediate development opportunity |
| Priority 3 | Later-stage or more complex project |
| Blocked | Progress depends on a missing requirement |
| Future Enhancement | Additional work proposed for an existing project |

These labels do not replace the official project status.

### Status Integrity Rules

- Learning a tool does not automatically mean a related project is in progress.
- Completing a tutorial does not automatically mean a portfolio project is completed.
- A project is not completed until its intended deliverables and documentation exist.
- Skills demonstrated should be recorded only when supported by actual work.
- A reviewed project must first satisfy completion requirements.
- External review is beneficial but not required if unavailable; self-review should be identified accurately.

# 7. Learning Progress vs. Portfolio Evidence

Learning progress and completed portfolio evidence are related but different.

| Activity | Learning Evidence | Completed Portfolio Project? |
|---|---|---|
| Watching an Excel tutorial | Learning notes | No |
| Practicing PivotTables | Practice workbook | Not necessarily |
| Completing a Python lesson | Exercise or notes | Not necessarily |
| Writing SQL practice queries | Query files | Not necessarily |
| Building a dashboard draft | Working project | Not yet |
| Completing and validating a dashboard | Final workbook and documented findings | Potentially, once requirements are met |
| Completing a case study | Analysis, findings, recommendations, and documentation | Yes, if standards are satisfied |

### Skills Evidence Principle

A skill should be listed as demonstrated when a completed activity provides clear evidence of its application.

For example:

**Skill:** Excel PivotTables

**Evidence:** A completed analytical workbook containing PivotTables used to answer documented business questions.

# 10. Weekly Portfolio Development Workflow

A manageable workflow will help me balance coursework, professional development, and other responsibilities.

### Suggested Weekly Learning Allocation

| Activity | Approximate Time |
|---|---|
| Learn or review one concept | 45–60 minutes |
| Practice with a small exercise | 60–90 minutes |
| Apply the concept to a project | 60–90 minutes |
| Document progress and questions | 30–45 minutes |
| Review and plan the next action | 15–30 minutes |

**Suggested Weekly Commitment:** Approximately 4–6 hours, adjusted for academic and personal responsibilities.

### Weekly Operating Principle

Focus on one primary portfolio project at a time while allowing a separate, small learning exercise when necessary.

### Example

The objective is to maintain progress without constantly switching between unrelated projects.

- [ ] Conclusions match the evidence

- [ ] Links work
- [ ] Confidential information is excluded
