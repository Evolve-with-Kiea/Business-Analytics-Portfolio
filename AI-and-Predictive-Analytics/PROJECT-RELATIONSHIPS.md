# AI Project Relationships & Development Classification

**Status:** Planning only. These are recommended classifications, not evidence that the projects have started.

## Why this register exists

AI projects should add a distinct capability to existing business analysis, rather than duplicate a dataset, dashboard, or conclusion. **Extension** means a new method on an existing or future baseline; **Standalone** means an independent analytical case study; **Integrated case study** combines several verified components.

## Build Order & Prerequisites

1. Complete or verify foundational Excel Sales Analysis; then consider the AI-Assisted Sales Performance extension.
2. Finish the remaining desktop validation for the existing AR & Collections workbook before using it as the verified baseline for AR risk analysis.
3. Add forecasting only when there are sufficient dated observations for a meaningful out-of-sample test.
4. Build AI reporting assistants after their source KPI definitions and reconciliations are verified.
5. Build integrated application prototypes after supporting calculations and components have been evaluated.

## Relationship Rules

- Keep baseline work in its canonical location; link to it instead of copying files.
- Create a separate AI case study only if it has a distinct business question, methodology and evaluation.
- A planned parent is **not** a completed prerequisite.
- Add real project links only after the underlying folder exists.
- Disclose reuse, AI involvement, privacy controls and validation evidence.
